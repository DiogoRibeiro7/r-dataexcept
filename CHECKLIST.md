# Package Quality Checklist

An audit of this repository against a general R packaging checklist, current
as of 0.1.0 (2026-09-27). Unticked boxes are genuinely not done, not
oversights.

---

## 1. Purpose & Scope

- [x] Clear purpose: classed, structured failures for R data and modelling
      code, in the failure format shared with the Python DataExcept package
- [x] Scoped: it adds the cross-language format, recovery metadata and classes
      for base R's text-only warnings, and leaves backtraces and condition
      formatting to base R and rlang
- [x] Package name checked against CRAN: `dataexcept` has no current or
      archived CRAN package

## 2. Package Structure

- [x] Standard layout: `R/`, `man/`, `tests/testthat/`, `inst/`
- [x] `DESCRIPTION` complete: `Authors@R` with ORCID, `License`, `URL`,
      `BugReports`, `Language: en-GB`, `Config/testthat/edition: 3`
- [x] `NAMESPACE` generated by roxygen2; 43 exports, nothing exported by
      accident (`dataexcept_classes()` and the reference index list them all)
- [x] Standard files: `README.md`, `NEWS.md`, `LICENSE`/`LICENSE.md`,
      `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`, `CITATION.cff`,
      `inst/CITATION`
- [x] Development-only files excluded from the build in `.Rbuildignore`

## 3. Dependencies

- [x] Minimal: `jsonlite` is the only import beyond base R (`stats`, `utils`);
      `otel` and `otelsdk` are suggested, for OpenTelemetry
- [x] `rlang` is optional (`Suggests`); rlang conditions are handled when it
      is installed and the code never requires it
- [x] Minimum R version declared (4.1) and tested in CI
- [x] No system requirements

## 4. Code Quality

- [x] Tidyverse style, enforced by styler and lintr in CI (`.lintr`)
- [x] Argument checks on every exported function, raising plain errors outside
      the condition hierarchy for programming mistakes
- [x] No `eval()`/`parse()` of external input; envelopes are data only
- [x] Internal helpers are not exported
- [ ] A vignette. The documentation lives on the MkDocs site instead; CRAN
      does not require one, but R users look for `browseVignettes()`

## 5. Testing

- [x] testthat 3e suite: 666 expectations across 11 files
- [x] Coverage 99.9%, measured by covr in CI with a 95% floor
- [x] Tests assert behaviour: messages, fields, class chains and envelope
      contents, not only classes
- [x] Cross-language contract tested against the Python package's own output:
      all eight reference envelopes round-trip exactly, redaction matches the
      Python implementation character for character, and `validate_envelope()`
      agrees with a JSON Schema validator on valid and invalid payloads
- [x] Locale-sensitive behaviour tested in English, German and the C locale
- [x] Edge cases covered: invalid UTF-8, deeply nested input, values JSON
      cannot represent, empty and partly named lists

## 6. Documentation

- [x] Every export documented with roxygen2, with runnable examples
- [x] README with installation, examples and badges
- [x] Documentation site (MkDocs Material): getting started, user guide,
      architecture, development, releases, and an API reference generated from
      the help pages
- [x] `NEWS.md` kept per version
- [x] Examples verified to do what they claim (the convergence examples fail
      to converge; the Python examples were run against the Python package)

## 7. Continuous Integration

- [x] `R CMD check` on macOS, Windows and Ubuntu, R devel, release, oldrel-1
      and 4.1
- [x] Lint, style and spelling checks
- [x] Coverage with a threshold
- [x] Envelope contract: R output validated by Python's `jsonschema`, and a
      weekly drift check against the Python package's `main`
- [x] Documentation built with `--strict` and deployed to GitHub Pages
- [x] Dependabot for GitHub Actions and the documentation toolchain
- [x] CI green on GitHub on every platform, R version and workflow

## 8. Security

- [x] `SECURITY.md` with private reporting, response targets, and an honest
      account of what redaction does and does not cover
- [x] Credentials in URLs redacted at construction and again on export
- [x] Reading untrusted envelopes bounded in depth before parsing and before
      walking
- [x] Workflows default to read-only permissions; only the Pages and release
      jobs request write access

## 9. Community

- [x] Contributing guide with the full local check, and procedures for adding
      condition types and warning rules
- [x] Contributor Covenant code of conduct
- [x] Issue forms (bug report, feature request) and a pull-request template
- [x] `CODEOWNERS`

## 10. Release & Distribution

- [x] Tag-driven release workflow: version checks against `DESCRIPTION` and
      `CITATION.cff`, `R CMD check --as-cran`, GitHub release with the tarball
      and the version's `NEWS.md` section
- [x] Citation metadata: `CITATION.cff` (validated) and `inst/CITATION`
- [x] First tagged release: [v0.1.0](https://github.com/DiogoRibeiro7/r-dataexcept/releases/tag/v0.1.0), published by the release workflow
- [ ] Zenodo DOI
- [ ] CRAN submission
- [ ] R-universe listing
